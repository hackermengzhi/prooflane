# 下单支付演示需求 v0.1

1. 登录用户可对有库存商品下单；未登录用户不得创建订单。
2. 数量必须为正整数，订单金额由服务端计算。
3. 创建订单后预留库存；库存不足不得创建有效订单。
4. 收到有效支付成功回调后订单变为已支付。
5. 同一支付回调重复提交不得重复扣库存或重复记录支付。
6. 无效签名回调不得更改订单。
7. 支付服务超时后订单保留待确认状态，不得伪报支付成功。

## 首个贯通场景

登录 → 下单 → 模拟支付回调 → 页面确认 → 查询订单和库存 → 检查服务日志。

预设缺陷计划：回调返回成功但未更新订单状态。测试必须发现并保留接口、页面和数据库状态证据。演示服务尚未实现。
