# 访问日志分析脚本需求

制作命令行脚本 `analyze.py`，分析类 Nginx 访问日志。运行环境只有 Python 标准库。

```sh
python analyze.py access.log --out report.json [--status 5xx]
```

- **L1 输入格式**：输入为 UTF-8 文本，每行采用以下 common log 格式（字段间单个空格，不含 referer 或 user-agent 后缀）：
  ```text
  127.0.0.1 - - [18/Oct/2026:10:00:00 +0000] "GET /health HTTP/1.1" 200 12
  ```
  第一字段为非空、无空白的来源标识；第二字段固定为 `-`；第三字段为非空、无空白的用户名或 `-`；方括号内为非空时间文本（无需校验日期）。请求方法由大写英文字母组成；请求目标以 `/` 开头且不含空白或双引号；协议为 `HTTP/数字.数字`（两部分均为一位或多位 ASCII 数字）。状态码为 100–599 的三位 ASCII 数字；最后字段为非负 ASCII 整数或 `-`。除行尾换行外，整行必须符合格式；空行也视为非法行。
- **L2 统计**：默认统计全部合法请求，`total_requests` 为请求总数；`status_counts` 按完整状态码统计，只包含实际出现的状态码，键为字符串，按数值升序排列。
- **L3 路径**：请求目标去掉第一个 `?` 及其后内容得到 URL 路径，不做百分号解码、不改变大小写。`paths` 为 `{"path": "/health", "count": 1}` 对象列表，按次数降序排列，同次数按路径的 Python 字符串字典序升序排列。
- **L4 过滤**：可选 `--status` 只接受 `1xx`、`2xx`、`3xx`、`4xx`、`5xx`；例如 `5xx` 包含 500–599（含端点）。提供过滤时，L2、L3 都只统计匹配的合法请求；无匹配时输出 `0`、`{}` 和 `[]`。非法过滤参数退出码为 2。
- **L5 输出**：成功时退出码为 0，stdout 为空；将 JSON 覆盖写入 `--out` 指定文件（其父目录已存在），编码 UTF-8，非 ASCII 字符直接输出。固定顶层字段顺序为 `total_requests`、`status_counts`、`paths`，路径对象字段顺序为 `path`、`count`。使用两个空格缩进（等同于 `json.dumps(..., ensure_ascii=False, indent=2)`），文件末尾恰好一个换行；相同记录任意调换行序，输出字节也应一致。不修改输入日志。
- **L6 非法行**：跳过全部格式非法的行，不崩溃。成功时 stderr 恰好输出一行 `skipped_lines: N`（末尾换行），`N` 为整个输入中的非法行数，包括过滤时遇到的非法行；没有非法行时也输出 `skipped_lines: 0`。
- **L7 缺失文件**：输入文件不存在时退出码为 2，stderr 输出非空错误说明，不创建输出文件。

例如上述单行输入应生成：

```json
{
  "total_requests": 1,
  "status_counts": {
    "200": 1
  },
  "paths": [
    {
      "path": "/health",
      "count": 1
    }
  ]
}
```
