# 领导—产品—开发—测试 Harness

用户负责下达目标和查收交付；领导 Agent 接收目标并委派给产品、开发、测试角色。每个角色有独立角色提示、当前任务和受限工具目录，模型可根据观察往返委派，不要求固定依次经过所有角色。

```sh
uv run prooflane harness '读取项目需求，实现自动化，交给测试验证后汇报结果' --workspace YOUR_PROJECT --allow-process
```

使用显式配置的模型端点（同通用 agent 的 PROOFLANE_LLM_* 环境变量）；可以通过 --checks 提供预置验收。没有配置时明确阻塞。此入口目前只支持模型驱动，测试中的模型动作由契约桩提供，不冒充真实模型验收。

| 角色 | 能力 |
| --- | --- |
| 领导 | 委派任务、接收报告、确认交付；不能直接调用执行工具 |
| 产品 | 读取文件、查看代码结构、制定一次性验收 |
| 开发 | 读取与修改文件、代码结构分析、已授权的进程执行 |
| 测试 | 读取文件、新建测试与报告文件（只能修改自己创建的文件）、代码结构分析、进程、HTTP、浏览器及实际验收 |

每个角色的提示包含对应专业做法：产品逐条列出编号需求并按交付物制定验收（找缺陷任务不要求被测系统通过）；开发逐条实现退出码、输出格式、分页、重试等细节并亲自运行；测试按等价类、边界值、状态与错误路径设计用例，失败时先复核需求、预期计算和稳定性，再记录产品缺陷。这些是提示层面的方法要求，效果以评测集实测为准。

角色之间通过领导交接任务和发现，最近共享记录以有界上下文提供，完整工具观察和事件写入本地运行目录与 SQLite。模型的决策不合规（JSON 无效、缺字段、越权调用工具、未通过验收就交付等）时，该决策不会执行，而是作为被拒记录反馈给模型自行纠正；连续 3 次被拒则任务阻塞。专家阻塞会返回领导处理；领导阻塞会形成用户可查收的报告。全局步数上限控制反复委派。

产品或用户确定验收定义，开发无权替换；只能由测试角色执行 verify。后续工具调用会清除旧验收结论。领导只有在当前测试证据全部通过后才能提交完成结果。报告显示实际角色和调用记录。

当前为串行角色协作。角色工具白名单是应用层约束，不是操作系统隔离：开发及测试的进程仍使用当前用户权限，能够间接修改验收脚本。因此尚不承诺恶意环境下的验收独立性。后续需要独立只读验收、执行沙箱、持久任务队列与恢复、跨角色上下文检索及真实模型效果评测。用户的最终查收不由领导 Agent 自动代替。
