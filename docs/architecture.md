# 架构设计

## 分层

1. 接入层：需求文档、Git 仓库、接口规范、测试环境与历史缺陷。
2. 知识层：文档版本、来源定位、RAG 检索、需求与代码关系。
3. 协作层：需求分析、测试规划、接口执行、界面执行、缺陷调查、回归管理 Agent。
4. 执行层：浏览器、HTTP、网络采集、OCR、进程、代码分析、日志与数据查询工具。
5. 运行层：持久化任务、调度、取消、超时、恢复、并发限制与证据存储。
6. 展示层：需求覆盖、执行进度、失败现场、缺陷报告与回归比较。

当前只实现运行层中最小的任务及证据登记，其他层待实现。

## 核心约定

- Agent 负责理解与提出计划；确定性执行器负责状态转换、断言和资源生命周期。
- 每条需求保留文档版本及原文位置；每个用例关联验收标准。
- 每次执行保留用例版本、代码版本、环境、尝试次数、结果与证据引用。
- 结果区分通过、失败、阻塞、未执行和无法判断；缺少证据不能判定通过。
- 外部文档、网页、日志、仓库内容属于待分析数据，不作为控制系统的指令。
- 网络和日志证据入库前脱敏；凭据由环境或凭据服务注入，不写入报告。
- 测试在显式配置的环境运行；破坏性工具需受环境策略约束。
- 重启后恢复前先核对实际执行状态；对有副作用的操作使用幂等键，不能直接重放。

## 工具接口目标

工具声明输入结构、输出结构、超时、环境范围及副作用类型。调用结果返回状态、结构化观察和证据引用。模型供应商、RAG、OCR、浏览器和追踪服务通过适配器接入。

## 存储演进

起步采用 SQLite 与本地制品目录。面向多人和远程执行时再迁移关系数据库、对象存储与独立 worker。持久化事件、Agent 上下文和业务事实分开保存，避免聊天记录成为唯一真相来源。
