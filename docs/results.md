# 评测结果与结论(实测记录)

本文件只记录**真实跑出来**的数字和可复现方法,不含推测。所有对比在同一模型(经中转的 `gpt-6.1-sol`)、同一批用例、同一套 Agent 看不到的隐藏评分器下进行。

## 1. 三种形态在 6 个本地用例上的对比

| 用例 | codex(裸单 Agent) | 万测王 单 Agent | 万测王 多角色 harness |
| --- | --- | --- | --- |
| reproduce-pagination | 1.00 | 1.00 | 0.00 |
| script-inventory | 1.00 | 1.00 | 0.00 |
| script-logparser | 1.00 | 1.00 | 0.00 |
| api-session | 1.00 | 0.96 | 0.00 |
| api-coupon | 1.00 | 0.50 | 0.00 |
| legacy-characterize | 0.50 | 0.50 | 0.50 |
| **均分** | **0.917** | **0.827** | **0.083** |

**结论(不粉饰):**
- 万测王的**单 Agent** 与一个强力裸 Agent(codex)**处于同一档**(0.827 对 0.917),是本项目当前可用、可推荐的形态。
- **多角色 harness** 在该模型下**不收敛**(跑满步数预算仍交不出通过验收的成果),已判定降级,不作为主推。
- 这 6 个用例为项目**自编**,只适合内部回归与形态对比,**不能**作为"优于他人"的对外证据(见第 3 节)。

## 2. 区分性能力:用独立证据识别"虚假完成"

万测王的评分来自 Agent **看不到**的隐藏评分器,并单独标记 `false_completion`(自称完成但实测不达标)。这是它与"裸 Agent"的关键区别。

- 实测证据:`legacy-characterize` 用例中,**codex 自称完成**,但其测试在正确实现上即失败(把某项费用断言为 400,实际为 450),被判 `false_completion=true`、0.50 分。
- 可现场复现的演示(确定性、离线、不需模型):
  ```sh
  uv run python examples/false-completion/demo.py
  ```
  输出:正确交付物 `score=1.000 false_completion=false`;看似完成实则不达标的交付物 `score=0.400 false_completion=true`。

## 3. 行业基准(对外可比,进行中)

自编题无法证明"领先"。项目已接入公开基准 **SWE-bench Lite**(真实仓库、真实 issue、真实 fail-to-pass 测试):

- `prooflane swebench`:加载真实实例 → 在其 base commit 上准备仓库并打上测试补丁 → 运行单 Agent(禁用进程执行,不运行目标仓库代码)生成补丁 → 按官方 JSONL 格式输出预测。
- 管道已在真实实例 `pytest-dev__pytest-7168` 上端到端验证(克隆、打补丁、产出合法 unified diff)。
- **尚未产出官方分数**:需要(a)用真实模型在实例上生成补丁(有模型调用成本),以及(b)官方 Docker 或托管评测来运行 FAIL_TO_PASS 打分。两者是获得可对外比较数字的前提。

## 4. 诚实的限制
