# 攻防深测模式：实现规格

目标：从攻击者视角研究用户的软件，将攻击面分析、攻击链构造、漏洞复现和修复回归连成闭环。该模式是待实现规格，现有调试工具和模型角色不等同于已完成本模式。

## 三类入口

| 入口 | 输入 | 执行任务 |
| --- | --- | --- |
| 仓库 | 项目目录、启动方式、测试账户与业务规则 | 分析输入来源、敏感操作、权限检查、依赖及数据流；形成候选问题；启动本地服务验证 |
| Web/API | 自有或授权环境、接口描述、不同权限账户 | 枚举入口，构造越权、注入、会话与业务状态测试，保留完整请求响应 |
| 本地靶场 | 可重复启动的漏洞版本与修复版本 | 验证检测能力、误报、攻击链和修复回归；使用隐藏验收判断真实结果 |

## 首批攻击面

- 身份与权限：未登录访问、水平与垂直越权、账户隔离、角色边界。
- 会话：令牌失效、注销、过期、固定会话、重复使用和并发状态。
- 输入：SQL/命令/模板注入、路径穿越、服务端请求、浏览器脚本与编码边界。
- 文件：上传类型、文件名、存储位置、解析器和解压路径。
- 业务：重复提交、并发竞争、金额与数量计算、状态跳转、重放和幂等。
- 依赖与配置：已知风险依赖、密钥暴露、调试入口和不当默认配置。

每类能力必须有可运行的漏洞与修复对照，不能仅凭工具名或提示词宣布支持。

## 角色分工

领导建立攻击面和验证优先级，产品梳理资产、身份与业务不变量，开发分析代码及候选攻击路径，测试执行可复现攻击与独立复核。领导依据证据汇总，不以模型猜测确认漏洞。

## 任务配置

任务记录目标目录、允许访问的环境、测试身份、请求预算、可接受的副作用及停止条件。强度意味着更深的攻击链和边界覆盖；配置用于保证结果可复现，并区分程序漏洞、测试故障和环境影响。真实密钥不写入漏洞报告。

## 交付物

攻击面清单 → 候选问题 → 攻击步骤与实际观察 → 最小复现 → 影响与根因 → 修复建议 → 同一用例的修复后回归。

发现记录必须区分：已复现、待验证、误报、环境阻塞。每条已复现问题绑定代码版本、目标环境、测试身份、请求响应或进程证据。支持多步攻击链，记录各步前置条件和取得的实际能力。

## 实施顺序与验收

1. 本地靶场：先跑通未授权访问、对象越权、路径穿越与重复提交四类问题，每类同时提供正确实现。
2. 仓库入口：分析候选问题并定位源码，启动项目，通过真实行为复现。
3. Web/API 入口：接入配置的环境和账户，运行同一类验证。
4. 扩展注入、文件、会话和业务并发用例，以隐藏评分衡量漏报、误报、覆盖与复现稳定性。

本规格不把“覆盖任何攻击”作为验收条件。验收使用明确攻击面、已执行用例、漏洞复现、正确版本误报率以及修复回归结果。
